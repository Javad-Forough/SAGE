Threat Model

Agent memory needs more than encryption at rest.

In the paper's cloud setting, storage is routinely snapshotted and restored, so logically deleted memory can silently reappear. Agent summaries, digests, and cached context can also survive their source memory.

Why SAGE matters

SAGE is presented as a memory architecture for persistent agent memory under storage rollback. Its main goal is transitive forgetting: when a scope is deleted, both the original memory and the dependent artifacts that rely on it become unusable, even if an older snapshot is later restored.

Logical deletion is insufficient Routine cloud snapshotting and restoration can cause deleted data to silently reappear.
Rollback revives stale state Older snapshots can recover previous ciphertexts unless key derivation tracks fresh monotonic state.
Derived artifacts must be forgotten too Summaries, digests, and synthesized context may continue influencing an agent after the original memory is deleted.

Trust Story

The abstract describes a local memory-layer mechanism: derive per-scope keys from sealed state and a rollback-protected epoch, then bind derived artifacts to source-scope metadata and revalidate those dependencies at retrieval time.

01

Derive per-scope encryption keys locally from a sealed root key.

02

Advance the rollback-protected epoch on deletion so earlier ciphertexts no longer decrypt.

03

Revalidate derived artifacts against source-scope epochs before they can be used again.

Architecture

A hardware-rooted lifecycle for sealed memory.

The paper describes SAGE as a sealed memory service using a small amount of trusted hardware state, such as a TPM monotonic counter together with sealed root-key storage, without requiring continuous interaction with external KMS.

Operational flow

A1

Seal a local root key

SAGE starts from sealed local hardware state rather than relying on a remote KMS for every operation.

A2

Derive per-scope encryption keys

Each scope gets keys derived from the root state together with the rollback-protected epoch.

A3

Record provenance for derived artifacts

Summaries, digests, and other derived artifacts carry source-scope and epoch metadata.

A4

Revalidate on retrieval

Rollback-restored artifacts fail if their source scope has already been forgotten under a newer epoch.
